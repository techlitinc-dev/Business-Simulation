orchestrator (`orchestrator/run_qa.sh --env <env>`) validates the matrix
below in preflight and phases 4–6. Values marked **(must set)** fail preflight
when wrong.

## Isolation guarantees (per phase)

| Phase | DB | Redis | LLM | Stripe | Email |
|---|---|---|---|---|---|
| 1 Unit | sqlite `:memory:` (conftest) | fakeredis | MockProvider | mocked SDK | console backend |
| 2 Integration | compose Postgres (qa) | compose Redis | MockProvider | mocked SDK | console backend |
| 3 E2E | compose Postgres, seeded | compose Redis | MockProvider | mocked 503 path | console backend |
| 4 Performance | compose Postgres (seeded) | compose Redis | MockProvider | n/a | console backend |
| 5 Security | compose Postgres | compose Redis | MockProvider | n/a | console backend |
| 6 Production | compose Postgres (seeded) | compose Redis | MockProvider | n/a | console backend |
| 7 Continuous | seeded staging/prod DB | Redis | MockProvider | n/a | n/a |

## Secrets handling (no human intervention)

- The orchestrator writes `.env` for the active env from
  `fixtures/env-<env>.env.template` (values above); every value is a literal,
  never an interactive prompt.
- Production secrets are **not** generated by QA: `--env production` requires
  an existing deployed stack and runs Phase 6 + 7 only (Phases 1–5 run in qa).
  `--smoke-only` also exists for this purpose.
- On completion the orchestrator redacts `.env` copies in `qa-results/`
  (JWT/Stripe/SMTP values replaced with `***`).
